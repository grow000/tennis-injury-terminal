# Tennis Injury Terminal

Одностраничный сайт про травмы, снятия и медицинские перерывы у топ-250 ATP и WTA.
Вкладки: **ATP**, **WTA**, **Снятия** (изменения в заявках турниров),
**Против кого ставить** (рейтинг физического риска перед US Open),
**Матчи** (расписание на неделю) и **Рейтинг** (топ-500 с очками к защите).

Клик по фамилии в любом месте — ленте, расписании, рейтинге или бегущей строке —
открывает карточку игрока: фото, страна, место в рейтинге, ближайший матч и все
медицинские сигналы за последние полгода.

## Файлы

| файл | что внутри |
|---|---|
| `index.html` | вся страница: вёрстка, стили, логика. Данных внутри нет |
| `data.js` | лента травм: тексты интерфейса (RU/EN), записи `NEWS`, составы сеток `DRAW`, метка `UPDATED` |
| `rankings.js` | рейтинги ATP и WTA, топ-500, с очками к защите |
| `matches.js` | расписание матчей на неделю вперёд |
| `players.js` | кэш фотографий игроков (ссылки на Wikimedia) |
| `update.py` | обновление ленты травм и рейтингов в `data.js` |
| `extra.py` | сбор рейтингов, расписания и фотографий |
| `og.html` | исходник картинки-превью для соцсетей |
| `og-preview.png` | сама картинка (1200×630), на неё ссылаются og-теги |
| `terminal.old.html` | самая первая версия сайта, до редизайна |

Открывать можно просто двойным кликом по `index.html` — сервер не нужен.

## Обновление данных

Само, каждые 3 часа: workflow `.github/workflows/update.yml` запускает `update.py`
и коммитит `data.js`, если что-то изменилось. Вручную — кнопкой Run workflow во
вкладке Actions или локально:

```bash
python update.py
```

`update.py` за один проход:

1. тянет рейтинги ATP и WTA (топ-300) и проставляет свежие места всем игрокам;
2. тянет ленту травм RotoWire и отбирает записи, которых ещё нет;
3. разбирает каждую: тур, турнир, рубрику `kind`, тип сигнала `sig`;
4. переводит на русский по шаблонам и вставляет в `NEWS`;
5. обновляет метку `UPDATED` — по ней сайт показывает дату и предупреждение
   «данные могли устареть», если прошло больше трёх дней.

Бот коммитит в тот же репозиторий, поэтому перед своими правками подтягивайте
его работу, иначе `git push` упрётся в расхождение:

```bash
git pull
```

Полезные режимы:

```bash
python update.py --dry-run    # показать, ничего не записывая
python update.py --show-ru    # прогнать переводчик по всей ленте и посмотреть текст
```

### Про перевод

Тексты RotoWire шаблонные, поэтому перевод сделан на правилах, а не машинный:
род берётся из тура, части тела и круги — из словарей в начале `update.py`.
Если конструкция незнакомая, запись всё равно публикуется, но с английским
текстом и пометкой `auto:true` — на карточке появляется серый ярлык «авто».
Так же помечаются игроки, которых ещё нет в словаре имён: их фамилия остаётся
латиницей, пока не пропишете `whoRu` руками.

Словарь имён строится сам — из тех записей, где `whoRu` уже заполнен.

Игроки вне топ-300 (например, возвращающиеся по защищённому рейтингу) в рейтинге
не находятся — их `rank` скрипт оставляет как есть и сообщает об этом.

`extra.py` собирает всё остальное:

- рейтинги ATP и WTA до 500-го места с движением и очками;
- «защищает» — из посевных таблиц US Open на Википедии, поэтому число есть только
  у сеяных;
- расписание на неделю вперёд, только матчи, где хотя бы один игрок входит в топ-500
  (иначе ленту забивают ITF и UTR);
- фотографии из Wikimedia Commons — порциями по 40 за запуск, найденное кэшируется
  в `players.js` и повторно не ищется.

Расписание дальше двух-трёх дней у источника обычно ещё не опубликовано —
пустые дни это норма, а не сбой.

## Как устроена запись

```js
{ts:"2026-08-16 15:10", who:"Casper Ruud", whoRu:"Каспер Рууд",
 tour:"atp", rank:20, code:"CIN", kind:"injury", sig:"retired",
 en:"retired with a <span class='flag'>back problem</span> …",
 ru:"снялся с <span class='flag'>проблемой спины</span> …",
 repl:"Alexei Popyrin", replRu:"Алексей Попырин",   // необязательно: замена в сетке
 src:"https://…", srcName:"RotoWire"}
```

- `kind` — рубрика ленты: `injury`, `withdrawal`, `returning`, `condition`
- `sig` — вес для расчёта риска: `retired`, `mto`, `illness`, `wd_mid`, `wd_pre`,
  `return`, `condition`, `rest`
- `out:true` — игрок недоступен не из-за формы (отстранение, пауза в карьере):
  из расчёта риска исключается
- текст начинается со сказуемого — имя подставляется перед ним

Коды турниров расшифровываются в `TOURN`, составы сеток US Open — в `DRAW`.

## Ссылки на состояние

Адресная строка хранит вкладку, фильтр, поиск и язык, поэтому ссылкой можно
поделиться:

```
index.html#/wta/injury?q=bencic&lang=ru
index.html#/fade
index.html#/player/Novak%20Djokovic
```

## Публикация на GitHub Pages

Один раз:

```bash
git remote add origin https://github.com/<логин>/<репозиторий>.git
git push -u origin main
```

Дальше в настройках репозитория: **Settings → Pages → Source: Deploy from a branch**,
ветка `main`, папка `/ (root)`. Сайт поднимется по адресу
`https://<логин>.github.io/<репозиторий>/`.

Там же **Settings → Actions → General → Workflow permissions** должно стоять
**Read and write permissions** — иначе боту нечем будет закоммитить `data.js`.

После первого деплоя замените в `index.html` относительный путь в `og:image` и
`twitter:image` на полный адрес картинки — иначе превью в Telegram не подтянется:

```html
<meta property="og:image" content="https://<логин>.github.io/<репозиторий>/og-preview.png">
```
